## 3. 실제 사진 21장 판정 결과

| 결과 | 장수 | 내용 |
|---|---|---|
| 품질 통과 + 종합 지수 산출 | 2 | 정면·고해상도·균일 조명 |
| 품질 통과, 신뢰도 부족으로 "추가 촬영 필요" | 4 | 얼굴 폭 250~330px 또는 한쪽 그림자 |
| 품질 미달 차단 | 15 | 고개 각도·기울기 4, 조명 불균일 5, 하관 가림(수염) 2, 얼굴 없음(측면·원경) 2, 저해상도 1, 흑백 1 (첫 번째 차단 사유 기준) |

- 스톡 인물 사진은 연출 조명·각도가 많아 가이드에 맞는 셀카와 조건이 다르다. 통과율은 실제 이용자 통과율을 대변하지 않는다.
- **어두운 피부톤**: 가장 어두운 사진(피부 L\* 45.7)은 yaw 23.6° 로 차단되어 지표 단계까지 가지 못했다. 밝기 판정은 피부가 아닌 하이라이트 퍼센타일을 쓰므로 이 사진이 "어두움"으로 오판되지는 않았다(조명 관련 차단 없음). 그 이상의 피부톤 공정성 검증은 못 했다.
- 수염: 옅은 수염 1장은 해당 영역만 `facial_hair` 로 null 처리되고 통과, 짙은 수염 2장은 하관 가림으로 차단.
- 분석 시간: 장당 1.5~2.7초(이 서버의 헤드리스 Chromium, 모델 로드 후). 실기기 성능은 측정하지 않았다.

## 4. 그 밖에 확인한 것 (E2E)

- 결과 JSON: 13영역, NaN 없음, 피부 나이·수분 값 없음, 측정 불가 목록 포함 (S01)
- 분석 중 네트워크: POST 는 `/api/events` 뿐, 외부 도메인 요청 0건 (P01)
- 영역 클릭 → 상세, 히트맵 전환, 3D 렌더링 (F05, F06)
- 케어: 추천 근거·주의사항, 공식몰 링크, 무료 체험 링크, 루틴 전환 (C01, C02)
- 기기 사용 제한 체크 → 기기 루틴·기기 상품 미표시, 응답이 결과 JSON 에 남지 않음 (C03)
- 시뮬레이션: 고지 문구·4/8/12주 표시 (M01). 단위 테스트로 피부 영역 밖 픽셀이 바뀌지 않음을 확인
- PDF(4쪽, 약 1.2MB)·PNG 저장 (R01, R02)
- 전후 비교: 같은 조건(리사이즈·재압축만 다름) → 전 항목 "변화 없음" (B01)
- 7개 언어 랜딩 렌더링, 영어 리포트에 한국어 잔존 없음 (L-\*)
- 저사양 기기 → 3D 미사용, 2D 표시 (MB3)
- 관리자: 미인증 401, 로그인, 통계 집계, 로그에 이미지·점수 없음, 설정 저장·반영, 비공식 URL 거부 (A01~A05)
- 잘못된 이벤트·과대 페이로드 거부 (A02)

## 5. 테스트 중 발견해 고친 결함

1. 선글라스처럼 눈이 완전히 가려져도 통과 → 눈 영역 밝기 비율 검사 추가
2. 기기 사용 제한 응답이 "분석 데이터 보기"에 노출 → 제거
3. 영어 리포트에 루틴 출처가 한국어로 표시 → 언어 중립 표기로 변경
4. 수염 영역에서 결·모공 지표가 포화 → 해당 영역 null 처리
5. 흑백 사진에서 색 지표가 0 으로 계산 → 흑백 차단
