# ROGUE LEGENDS 플레이 테스트 안내

작성 2026-11-27 · 대상 규칙 v2 · 진행/중단 기준은 [DEVELOPMENT_PRIORITY.md](DEVELOPMENT_PRIORITY.md) §3을 따릅니다.

## 1. 무엇을 알아내려는가
| 질문 | 어떻게 보나 |
|---|---|
| "한 판 더" 하고 싶어지는가 | 테스터당 원정 수, 7일 안에 다시 왔는지(포털 실측) — **목표 숫자는 첫 2주 실측을 보고 정함** |
| 규칙 비틀기(화상 반감·방어=공격)가 재미의 중심인가 | 카드 선택률: 화상·방어 계열 카드가 고르게 뽑히는지, 아니면 늘 건너뛰는지 |
| 어디서 막히는가 | 원정이 끝난 막·층, 그때 서 있던 적 |
| 너무 길거나 짧은가 | 원정당 시간 (목표 1막 25–35분) |

## 2. 테스터가 할 일 (5–10명, 각 3판 이상)
1. 포털(BIT PARK `/#play/rogue-legends` 또는 airobotphysical.com)이나 `apps/game-lab/rogue-legends`를 로컬로 열어 플레이합니다.
2. 처음 2판은 설명 없이 — 막힌 곳을 메모만 합니다.
3. 끝나면 첫 화면의 **「기록 내보내기 (JSON)」**를 눌러 파일을 보내 줍니다. 파일에는 시드·행동 목록·시간·결과만 있고 개인 정보는 없습니다.
4. 짧은 설문: 가장 재미있던 순간 1개, 가장 답답했던 순간 1개, 다시 하고 싶은지(1–5).

## 3. 모인 파일 분석
```bash
cd apps/game-lab/rogue-legends
node tools/playtest-report.mjs tester1.json tester2.json … --out ../../../docs/indie-studio/playtests/2026-12-XX.md
```
리포트는 모든 원정을 게임 규칙으로 **다시 재생해서** 만듭니다(따로 쌓은 통계가 아님). 다른 규칙 버전의 원정은 세기만 하고 재생하지 않습니다.
나오는 표: 영웅·난이도별 판수·승리·도달 층·시간 / 끝난 위치 / 쓰러질 때 서 있던 적 / 카드별 제시·선택·선택률 / 상점 구매 / 승리 원정의 유물.

## 4. 결과를 보고 하는 일
- 선택률이 아주 낮은 카드(예: 10% 미만) → 수치 조정 또는 교체. 아주 높은 카드(80%↑) → 너무 강한지 확인.
- 한 층·한 적에 죽음이 몰리면 그 적의 행동 순환·체력을 조정 → `node tools/sim.mjs 300`으로 봇 곡선이 크게 무너지지 않는지 확인.
- 규칙을 바꾸면 `RULES_VERSION`을 올리고, BIT PARK 검증기를 다시 vendor 하도록 포털 PR을 보냅니다(이전 버전 기록은 그 버전 규칙으로만 재생됨).
- §1의 "한 판 더" 반응이 없으면 DEVELOPMENT_PRIORITY의 기준대로 규칙 비틀기를 다시 고르고, 두 번 실패하면 주력을 SURVIVAL WORLD로 옮깁니다.
