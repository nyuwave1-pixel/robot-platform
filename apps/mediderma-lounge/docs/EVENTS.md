# 이벤트 · 프로모션 · 오픈 라운지 운영 안내

## 1. 공식 이벤트 올리기 (운영자)
`public/events.json` 의 `events` 배열을 고쳐 배포하면 모든 플레이어의 **EVENT** 버튼에 안내가 뜹니다 (게임 코드 수정 없음).

| 필드 | 설명 |
|---|---|
| `id` | 영문 소문자·숫자·하이픈. 보상 수령 기록의 기준이므로 한 번 쓴 id 는 다시 쓰지 않습니다 |
| `ko` / `en` | 제목 |
| `descKo` / `descEn` | 설명 (200자 안쪽) |
| `start` / `end` | ISO 시각. 한국 시간은 `2026-12-01T00:00:00+09:00` 처럼 `+09:00` |
| `color` | 배너 색 `#rrggbb` |
| `reward` | (선택) 기간 중 한 번 받는 선물 `{ "coins": 300, "gems": 5, "stars": 2 }` · 상한 코인 5000 · 젬 50 · 스타 30 |
| `cta` | (선택) 바로 가기: `plaza` · `lounge` · `life` · `shop` · `care` |

- 진행 중인 이벤트와 14일 안에 시작하는 이벤트가 보입니다. 끝난 이벤트는 저절로 사라집니다.
- 형식이 틀린 항목은 무시되고 나머지는 정상 표시됩니다 (`tests/events.test.ts` 가 배포 파일을 검사).

## 2. 오픈 라운지 (플레이어)
- 내 라운지에 있는 동안 라운지가 **열려** 있으면 다른 플레이어가 실시간으로 들어옵니다 (EVENT → 내 라운지에서 열기/닫기).
- 방문: EVENT → 열린 라운지 목록에서 고르거나 친구 코드 6자리 입력. 광장에서 홍보 중인 라운지를 방문해도 주인이 접속해 있으면 실시간입니다.
- 방문객이 들어오면 주인은 LOUNGE POINT 를 받습니다 (하루 한도는 광장 방문과 같음).

## 3. 라운지 이벤트 · 공지 (라운지 주인)
- 오픈 파티 · 뷰티 클래스 · 포토 데이 · 타임 세일 중 하나를 코인을 내고 열면 정해진 시간 동안 열린 라운지 목록 맨 위에 보이고, 방문객은 혜택을 받습니다 (라운지마다 하루 한 번, 하루 5곳까지). 주인은 하루 3번까지 열 수 있습니다.
- 공지: 정해진 안내 문구만 보낼 수 있습니다 (자유 채팅 없음 — 미성년자 보호·운영 부담).

## 기술 메모
- Supabase Realtime 공개 채널(Presence + Broadcast)만 사용, 데이터베이스 저장 없음: 라운지 `mdl-lounge-<코드>`, 로비 `mdl-lounge-lobby`.
- 다른 사람이 보낸 값은 모두 검증 (`cleanLook` · `cleanLounge` · `cleanEvent` · `cleanLobby`). 연결이 안 되면 혼자서 동작합니다.
- 서버가 없으므로 보상은 클라이언트에서 지급됩니다. 실제 경품·결제가 걸린 프로모션이 필요하면 서버 검증(Supabase 테이블 + RLS/Edge Function)으로 옮겨야 합니다.

## 4. 주간 라운지 꾸미기 콘테스트
- EVENT → **콘테스트** 탭. 한 주(한국 시간 월요일 0시 ~ 일요일 24시)에 내 라운지를 출품하고, 다시 내면 지금 모습으로 바뀝니다.
- 다른 출품작에 하트(한 주 5표, 작품마다 한 번, 내 라운지 제외). 순위표에서 **구경**하면 그 라운지 출품 사진으로 들어가고, 주인이 접속해 있으면 실시간 방문이 됩니다. 방문 화면 아래 **하트** 버튼으로도 투표.
- 보상(지난 주 결과로 한 번): 1위 3000 코인·50 젬 / 2~3위 2000·30 / 4~10위 1000·10 / 하트를 받은 출품작 300 코인.
- 서버: Supabase 프로젝트의 `mdl_contest` 스키마(공개 안 됨) + 검증 함수 `mdl_contest_enter/vote/board/me` (SQL: `supabase/mdl_lounge_contest.sql`).
  친구 코드 + 기기에 저장된 비밀값으로 본인 확인 — 남의 코드로 출품·투표할 수 없습니다. 같은 저장을 다른 기기에서 쓰면 그 기기에서는 콘테스트 참여가 막힙니다.
- 한계: 로그인이 없어 한 사람이 저장을 여러 개 만들어 표를 늘리는 것은 막지 못합니다. 실제 경품을 걸 때는 로그인(Supabase Auth) 연동이 필요합니다.
- 운영 SQL 예: 이번 주 순위 `select * from public.mdl_contest_board();` · 부정 출품작 삭제 `delete from mdl_contest.entries where week = '2026-W48' and code = 'XXXXXX';`

## 5. 라운지 방명록
- 다른 플레이어 라운지를 방문하면 아래 배너의 **방명록** 버튼으로 스티커 6종 + 응원 문구 10종 중에서 골라 남긴다. 자유 글은 받지 않는다.
- 라운지마다 하루(한국 시간) 한 번, 하루 최대 10곳. 처음 남길 때마다 15 코인.
- 내 라운지에 남겨진 글은 EVENT 패널 **방명록** 탭에서 최근 30개를 본다. 새 글이 오면 EVENT 버튼에 숫자가 붙는다.
- 서버: `supabase/mdl_lounge_guestbook.sql` (테이블 `mdl_contest.guestbook`, RPC `mdl_guest_write` · `mdl_guest_list`). 본인 확인은 콘테스트와 같은 기기 비밀값을 쓴다. 라운지마다 최근 100개만 보관한다.
- 문구·스티커를 늘릴 때는 `src/net/guestbook.ts` 의 목록에 추가한다 (서버 허용 범위: 문구 0–19, 스티커 0–9).

## 6. 포털(AIRobotVerse) 연동
- 포털 게임 섹션(`airobotverse-` 저장소 `src/components/MedidermaLoungeSection.tsx`)이 콘테스트 순위 · 이벤트 · 지금 열린 라운지를 보여 준다.
- 포털은 `/events.json` 을 읽는다 (`vercel.json` 에서 이 파일만 CORS 허용). events.json 을 고치면 포털에도 5분 안에 반영된다.
- 게임으로 들어오는 링크: `?visit=친구코드` (열린 라운지 바로 방문, 닫혀 있으면 열린 라운지 탭) · `?open=contest|events|lounges` (해당 탭 열기). 게임을 시작한 뒤 한 번만 적용되고 주소에서 지워진다.
- 포털 안 플레이 (2026-11-25): 포털 `/games/play/beauty-life/` 가 이 게임을 iframe 으로 띄운다 (`games-config.ts` 의 `beauty-life`). 포털 주소의 `?visit=` · `?open=` 은 게임 주소로 그대로 넘어간다.
- 포털 RP: 포털 안에서 뷰티 케어를 마칠 때마다 `src/net/portal.ts` 가 `{type:"game_result", game:"beauty-life", score, rp:40}` 을 허용된 포털 주소(airobotphysical.com · www · web.app)로만 보낸다. 포털이 로그인 사용자에게 하루 1회 RP 를 준다.
