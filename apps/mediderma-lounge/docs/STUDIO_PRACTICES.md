# Studio Practices — claude-code-game-studios 분석과 반영

분석 대상: https://github.com/donchitos/claude-code-game-studios (MIT, v1.3.0, 2026-11-09 기준 커밋 `abc0de7`)

## 무엇인가
Claude Code 로 게임을 만드는 **작업 방식 템플릿**이다. 게임 코드가 아니라 `.claude/` 아래의 에이전트 49개, 스킬(슬래시 명령) 70여 개, 훅 18개, 코드 규칙 14개, 그리고 엔진별 참고 문서로 이루어져 있다. 핵심 흐름은 "한 장짜리 브리프 → 플레이 가능한 첫 빌드 → 고정된 체크 → 한 번에 한 기능씩 성장"이다.

## 이 게임에 반영한 것
| 프레임워크의 규칙 | 이 게임에서 한 일 | 위치 |
|---|---|---|
| 그림을 이모지로 그리지 않는다 ("no emoji art") | UI 아이콘·재화·잠금 표시 등 이모지 약 100곳을 직접 그린 SVG 아이콘 28종으로 교체. 문구에서도 그림 이모지 제거 | `src/ui/Icon.tsx`, `src/i18n/*.json` |
| 게임 수치는 데이터 파일에 두고 코드에 박지 않는다. 값마다 `value·min·max·step` | 보상·경제·고객·성장·펫·스테이션·미니게임 수치 50개를 `config.json` 으로 분리. 코드는 `tune("care.zone_skin_exp")` 로 읽는다 | `src/data/config.json`, `src/data/config.ts` |
| 튜닝을 요청하면 값마다 슬라이더가 있는 트윅 패널 | `?debug` 에서 TWEAK 패널. 바꾼 값은 메모리에만 적용 | `src/ui/Tweaks.tsx` |
| 로직은 자동 단위 테스트가 통과해야 한다 | 46개 테스트: 상품 DB·루틴 정합성, 케어 세션 상태 전이와 보상 공식, 고객 결제, 구매·가구·퀘스트·저장, 펫·스테이션·친구 초대·미니게임 | `tests/*.test.ts`, `npm test` |
| "파싱 통과는 실행이 아니다" — 실제로 띄워서 본 스크린샷을 남긴다 | 스모크 체크 스크립트가 게임을 열어 9개 행을 판정하고 스크린샷을 저장 | `scripts/smoke-check.mjs`, `qa/evidence/`, `npm run smoke` |
| 스모크 체크 행: 열림 · 입력에 반응 · 글자 크기 · 콘솔 오류 | `boots` `responds` `care` `station` `pet` `minigame` `save` `text` `console`. 판정할 수 없으면 통과가 아니라 `not_assessed` | `qa/smoke-latest.tsv` |
| 너무 작은 글자는 고친다 | 8~11px 이던 글자 104곳을 12~13px 로 올림. 체크 기준 12px | `src/ui/*.tsx` |
| 모든 애니메이션은 건너뛸 수 있어야 한다 | 성장 시네마틱에 건너뛰기 버튼 | `src/ui/Hud.tsx`, `src/three/World.tsx` |
| 한 장짜리 게임 브리프가 설계의 출발점 | `GAME_BRIEF.md` 작성 (요청 원문의 말, 첫 1분, 도전, 기능, 나중으로 미룬 것) | `docs/GAME_BRIEF.md` |
| 시스템 설계서는 8개 절(개요·판타지·규칙·공식·예외·의존성·튜닝·수용 기준) | 케어 시스템을 그 형식으로 작성. 공식은 config 키로 연결 | `docs/gdd/care-system.md` |
| 스크립트는 관찰을 적고 판정은 사람이 한다 / 재미는 사람이 플레이해서 본다 | 스모크 체크는 재미·난이도를 판정하지 않는다고 명시. 결과물에 "사람이 아직 플레이하지 않음"을 적는다 | 아래 "현재 상태" |

## 반영하지 않은 것과 이유
| 항목 | 이유 |
|---|---|
| `.claude/` 프레임워크 전체 설치 (에이전트·스킬·훅·권한 규칙) | 이 저장소는 로봇 플랫폼·버스데이 크림과 함께 쓰는 모노레포다. 루트에 설치하면 **모든 앱의 Claude 세션**에 훅과 "파일을 쓰기 전에 매번 묻기" 모드가 걸린다. 저장소 운영 방식을 바꾸는 결정이라 소유자 확인 없이 하지 않았다 |
| "글자 14px 이상(1080p)" 기준 | 캔버스에 직접 그리는 게임 기준이다. 이 게임은 정보량이 많은 DOM 패널 UI 라 12px 로 잡았다. 14px 기준으로는 **미달**이다 |
| 키는 `snake_case`, 파일은 `[system]_[name].json` | `config.json` 은 따랐다. 기존 TS 데이터(`products.ts` 등)는 타입 안전성을 위해 그대로 두었다 |
| ADR(아키텍처 결정 기록), 스프린트·스토리 문서 | 1인·MVP 규모라 `TECHNICAL_ARCHITECTURE.md` 로 대신한다 |
| 시드 고정 리플레이 회귀 | 게임에 난수 의존 로직(고객 스폰)이 적고, 단위 테스트가 결정적 로직을 덮는다. 고객 스폰에 시드를 넣는 것은 다음 작업 |
| 게임패드 입력, 색각 보정 모드, 글자 크기 조절 | 미구현. 로드맵에 추가 |
| three.js r186 참고 문서(Clock→Timer, PCFSoftShadowMap 제거 등) | 이 게임은 three 0.169 에 고정돼 있어 해당 변경의 영향을 받지 않는다. 업그레이드할 때 이 문서를 체크리스트로 쓴다 |

## 코드 사용 여부
프레임워크의 코드·스크립트·문서 본문은 **복사하지 않았다.** 규칙과 절차를 읽고 이 게임에 맞게 새로 작성했다. MIT 라이선스라 가져다 쓸 수는 있으며, 그 경우 저작권 고지를 포함해야 한다.

## 현재 상태 (프레임워크의 인수인계 카드 형식)
- **통과:** 타입체크, 빌드, 단위 테스트 46개, 스모크 체크 9행
- **판정하지 않음:** 재미, 난이도, 케어 조작의 손맛, 실제 GPU·실제 휴대폰에서의 성능
- **짐작으로 정한 것:** 모든 밸런스 수치(성장 기준, 보상, 가격) — 플레이 기록 없이 정했다
- **사람이 아직 플레이하지 않음**

## 라운지 등급 (v0.3)

- 출처: UNI&CORE New Benefit Plan v1 안내서. 직급 10단계의 이름·코드·순서와 "GTV·STV·PLV 세 기준, 단계마다 2배" 구조만 가져왔다.
- 게임 수치는 공식 표의 1/10 이고 의미도 게임 활동으로 바꿨다: GTV = 구매 PV + 소비 PV + 고객 등록 포인트, STV = 고객 등록 포인트, PLV = 제품 소비 PV.
- PV 는 공식몰 표시가 1,000원당 1 (`rank.krw_per_pv`). 고객 1명 = 별 × 10 포인트, 직원 자동 케어는 60%.
- 등급 보너스: 고객 결제·LOUNGE POINT 등급당 +3%, 하루 한 번 구독 보너스(등급 × 25 COIN), 승급 시 1회 보너스. 모두 `config.json` 의 `rank.*` 로 조정.
- 실제 수당·소득 수치는 게임에 넣지 않는다. 등급 화면에 "실제 직급·수당·소득과 무관" 안내를 항상 표시한다.
- 테스트: `tests/rank.test.ts` (6개).

### 등급 외형 (v0.3.1)

- `Character` 의 `rank` prop 으로 그린다. 플레이어에게만 적용하고, 등급 화면에서 표시/숨김을 고를 수 있다 (`look.hideRank`).
- 장식: M+ 브로치 → DR+ 등급 색 케이프릿 → ID+ 망토 → IVP+ 골드 티아라·반짝임 → IPD+ 왕관·긴 망토·골드 오라.
- 얼굴: 등급이 오를수록 속눈썹·아이섀도·눈 크기와 광채·립 글로스·광대 하이라이트·피부 윤기가 더해진다. 게임 판타지 연출이며 제품 효능 표현이 아니다.

### Blender 캐릭터 파츠 (v0.3.2)

- 유료 3D 생성 서비스 대신 무료·오픈소스인 Blender 로 만든다. `tools/blender/build_assets.py` 가 원본이다.
- 통짜 캐릭터 모델이 아니라 단위 크기 파츠다: `char_head`(갸름한 턱선 + 귀) · `char_hand`(엄지와 손가락) · `char_shoe`(메리제인: 밑창·스트랩·단추) · `char_hem`(치맛단 러플) · `char_bow`(가슴 리본). 합계 약 8,500 삼각형, 210 KB.
- 게임이 파츠를 체형 치수로 스케일하고 재질(skin · shoe · accent)을 캐릭터 색으로 바꾸므로 헤어·의상·색상 커스터마이징과 5단계 성장, 등급 외형이 그대로 유지된다.
- 파일을 못 불러오면 코드로 만든 기본 형상이 대신 보인다.

### Blender 헤어 (v0.3.3)

- 헤어 11종 전부를 Blender 로 만들었다 (`build_assets.py --hair` 로 헤어만 다시 내보낼 수 있다). 두피 쉘 + 굵기가 변하는 가닥(커브 튜브)으로 구성한다.
- `hair_<스타일>.glb` 는 머리에 고정된 부분, `hair_<스타일>_sway.glb`(twin · pony · braid · long · wave · hime)는 걸을 때 흔들리는 부분이다.
- 긴 머리의 sway 는 세로 길이 1 로 만들고 게임이 성장 단계의 몸 길이에 맞춰 세로로 늘린다.
- 재질 `hair` 는 게임이 머리색 재질로 바꿔 끼운다. 스타일당 2,300~6,700 삼각형, 전체 1.5 MB 이며 캐릭터는 자기 스타일 파일만 불러온다.

### Blender 가구 (v0.3.4)

- 가구 11종을 Blender 로 만들었다 (`build_assets.py --furniture`): 몬스테라 화분 · 튤립 꽃병 · 아치 거울 · 플로어 램프 · 마블 커피 테이블 · 책장 · 캣 타워 · 펫 쿠션 · 디퓨저 · 골드 사이드 테이블 · 원형 진열대. 합계 약 1.1 MB.
- 조명(램프의 포인트 라이트)은 게임 코드가 덧붙인다. 파일을 못 불러오면 코드 형상(`FurnitureFallback`)이 대신 보인다.
- 헤어 뒷모습: 보브·픽시는 가닥이 정수리에서 두피 곡면을 따라 내려오도록 고쳤다 (게임 기본 시점이 뒷모습이다).

### Blender 가구 2차 (v0.3.5)

- 화장대(서랍·전구 거울·스툴) · 플라워 아치 포토존 · 러그 · 라탄 파티션 · 아쿠아리움을 추가해 Blender 가구는 16종이 됐다.
- 아쿠아리움의 물(반투명)과 조명, 포토존의 MEDIDERMA 글자는 게임 코드가 그린다.
- 남은 코드 형상: 캐릭터 몸통·치마 본체, 소파류(이미 Blender), 로고 사인, 디바이스 거치대.
