# Studio Practices — claude-code-game-studios 분석과 반영

분석 대상: https://github.com/donchitos/claude-code-game-studios (MIT, v1.3.0, 2026-11-09 기준 커밋 `abc0de7`)

## 무엇인가
Claude Code 로 게임을 만드는 **작업 방식 템플릿**이다. 게임 코드가 아니라 `.claude/` 아래의 에이전트 49개, 스킬(슬래시 명령) 70여 개, 훅 18개, 코드 규칙 14개, 그리고 엔진별 참고 문서로 이루어져 있다. 핵심 흐름은 "한 장짜리 브리프 → 플레이 가능한 첫 빌드 → 고정된 체크 → 한 번에 한 기능씩 성장"이다.

## 이 게임에 반영한 것
| 프레임워크의 규칙 | 이 게임에서 한 일 | 위치 |
|---|---|---|
| 그림을 이모지로 그리지 않는다 ("no emoji art") | UI 아이콘·재화·잠금 표시 등 이모지 약 100곳을 직접 그린 SVG 아이콘 28종으로 교체. 문구에서도 그림 이모지 제거 | `src/ui/Icon.tsx`, `src/i18n/*.json` |
| 게임 수치는 데이터 파일에 두고 코드에 박지 않는다. 값마다 `value·min·max·step` | 보상·경제·고객·성장 수치 35개를 `config.json` 으로 분리. 코드는 `tune("care.zone_skin_exp")` 로 읽는다 | `src/data/config.json`, `src/data/config.ts` |
| 튜닝을 요청하면 값마다 슬라이더가 있는 트윅 패널 | `?debug` 에서 TWEAK 패널. 바꾼 값은 메모리에만 적용 | `src/ui/Tweaks.tsx` |
| 로직은 자동 단위 테스트가 통과해야 한다 | 30개 테스트: 상품 DB·루틴 정합성, 케어 세션 상태 전이와 보상 공식, 고객 결제, 구매·가구·퀘스트·저장 | `tests/*.test.ts`, `npm test` |
| "파싱 통과는 실행이 아니다" — 실제로 띄워서 본 스크린샷을 남긴다 | 스모크 체크 스크립트가 게임을 열어 6개 행을 판정하고 스크린샷을 저장 | `scripts/smoke-check.mjs`, `qa/evidence/`, `npm run smoke` |
| 스모크 체크 행: 열림 · 입력에 반응 · 글자 크기 · 콘솔 오류 | `boots` `responds` `care` `save` `text` `console`. 판정할 수 없으면 통과가 아니라 `not_assessed` | `qa/smoke-latest.tsv` |
| 너무 작은 글자는 고친다 | 8~11px 이던 글자 104곳을 12~13px 로 올림. 체크 기준 12px | `src/ui/*.tsx` |
| 모든 애니메이션은 건너뛸 수 있어야 한다 | 성장 시네마틱에 건너뛰기 버튼 | `src/ui/Hud.tsx`, `src/three/World.tsx` |
| 한 장짜리 게임 브리프가 설계의 출발점 | `GAME_BRIEF.md` 작성 (요청 원문의 말, 첫 1분, 도전, 기능, 나중으로 미룬 것) | `docs/GAME_BRIEF.md` |
| 시스템 설계서는 8개 절(개요·판타지·규칙·공식·예외·의존성·튜닝·수용 기준) | 케어 시스템을 그 형식으로 작성. 공식은 config 키로 연결 | `docs/gdd/care-system.md` |
| 스크립트는 관찰을 적고 판정은 사람이 한다 / 재미는 사람이 플레이해서 본다 | 스모크 체크는 재미·난이도를 판정하지 않는다고 명시. 결과물에 "사람이 아직 플레이하지 않음"을 적는다 | 아래 "현재 상태" |

## 반영하지 않은 것과 이유
| 항목 | 이유 |
|---|---|
| `.claude/` 프레임워크 전체 설치 (에이전트·스킬·훅·권한 규칙) | 이 저장소는 로봇 플랫폼·버스데이 크림과 함께 쓰는 모노레포다. 루트에 설치하면 **모든 앱의 Claude 세션**에 훅과 "파일을 쓰기 전에 매번 묻기" 모드가 걸린다. 저장소 운영 방식을 바꾸는 결정이라 소유자 확인 없이 하지 않았다 |
| "글자 14px 이상(1080p)" 기준 | 캔버스에 직접 그리는 게임 기준이다. 이 게임은 정보량이 많은 DOM 패널 UI 라 12px 로 잡았다. 14px 기준으로는 **미달**이다 |
| 키는 `snake_case`, 파일은 `[system]_[name].json` | `config.json` 은 따랐다. 기존 TS 데이터(`products.ts` 등)는 타입 안전성을 위해 그대로 두었다 |
| ADR(아키텍처 결정 기록), 스프린트·스토리 문서 | 1인·MVP 규모라 `TECHNICAL_ARCHITECTURE.md` 로 대신한다 |
| 시드 고정 리플레이 회귀 | 게임에 난수 의존 로직(고객 스폰)이 적고, 단위 테스트가 결정적 로직을 덮는다. 고객 스폰에 시드를 넣는 것은 다음 작업 |
| 게임패드 입력, 색각 보정 모드, 글자 크기 조절 | 미구현. 로드맵에 추가 |
| three.js r186 참고 문서(Clock→Timer, PCFSoftShadowMap 제거 등) | 이 게임은 three 0.169 에 고정돼 있어 해당 변경의 영향을 받지 않는다. 업그레이드할 때 이 문서를 체크리스트로 쓴다 |

## 코드 사용 여부
프레임워크의 코드·스크립트·문서 본문은 **복사하지 않았다.** 규칙과 절차를 읽고 이 게임에 맞게 새로 작성했다. MIT 라이선스라 가져다 쓸 수는 있으며, 그 경우 저작권 고지를 포함해야 한다.

## 현재 상태 (프레임워크의 인수인계 카드 형식)
- **통과:** 타입체크, 빌드, 단위 테스트 30개, 스모크 체크 6행
- **판정하지 않음:** 재미, 난이도, 케어 조작의 손맛, 실제 GPU·실제 휴대폰에서의 성능
- **짐작으로 정한 것:** 모든 밸런스 수치(성장 기준, 보상, 가격) — 플레이 기록 없이 정했다
- **사람이 아직 플레이하지 않음**
